# seiyu-asa / もしあの時

毎朝の西友で買う **お菓子 + 昼メシ + ペットボトル** を、価格・カロリー・過去の満足度から提案するスマホ向けWebアプリです。

夕方の買い物は混ぜず、出勤前の短い買い物だけに絞っています。

## 方針

- ユーザー体験を最優先
- 食事禁止や運動ノルマを押し付けない
- 「何を食べるか」を西友の商品から選びやすくする
- 買って後悔した商品を忘れない
- 使うほど自分向けの商品辞書が育つ
- **有料API・有料SaaS・アプリ内課金は使わない**

## 実装済み

### 朝の3点セット

- お菓子 + 昼メシ + 飲み物をまとめて提案
- 好きな1カテゴリを固定
- 残り2カテゴリを価格・kcal・採用率・満足/後悔・最近食べた回数から提案
- 「別のセット」で再提案
- 同じ日に押し直した未確定セットは差し替え
- 最近の「食べた」記録が2日以上あると、今日のセットとの差額・kcal差を表示
- 選んだカテゴリと商品を端末に記憶

### バーコード / 商品検索

- JAN/EANバーコード読み取り（対応形式を端末側で確認）
- バーコード写真からの読み取り
- JAN手入力フォールバック
- 商品名から西友ネットスーパーを検索するフォールバック
- JANの空白・ハイフン等を除去して正規化
- **JAN → 西友ネットスーパー商品詳細ページを最優先で照合**
- 西友で見つからない場合は Open Food Facts を無料の商品DBとして補完
- 商品名が分かれば西友ネットスーパー公開見学ページも検索
- 店頭価格 / 西友ネットスーパー参考価格 / kcal を分けて保存
- 店頭価格とネット参考価格の差額表示
- 西友検索候補 → JAN詳細 → 今日の優先商品、までアプリ内でつなぐ
- スキャン商品 / 代替商品をそのまま「今日の3点」の優先商品にできる
- 西友側から同系統の代替候補をオンデマンド検索し、価格・kcalで比較
- 過去の後悔理由が「高い」「カロリーの割に満足しない」なら代替順位へ反映
- 西友公式の商品在庫検索へJANをコピーして遷移

> 西友ネットスーパーの公開情報は見学ページの参考情報です。実際の品揃え・価格はログイン後の配送エリア等で異なる場合があります。

### 履歴 / 学習

- 日付ごとの「買う予定 / 食べた」一覧
- 日ごとの食べた合計金額・kcal
- 今月の記録日数・金額・kcal・ネット参考価格との差・後悔件数
- 店頭で別商品へ選び直した「もしあの時」を記録
- 選び直しによるkcal差・価格差と、体脂肪1kg≒約7,000kcalの単純換算目安を表示（減量保証ではない）
- 商品ごとの提案回数 / 採用回数 / 選ばれ率 / 食べた回数
- 「よかった / 微妙 / もう買わない」
- 後悔理由
  - 高い
  - 量が足りない
  - カロリーの割に満足しない
  - 味が好みじゃない
  - その他
- NG商品を朝の提案から除外
- NG商品を再スキャンすると過去の後悔を警告
- NG解除
- 日ごとの予定を一括で「食べた」に確定
- 履歴削除
- 商品辞書を商品名・JANで検索

### 商品データ方針

- 商品マスタをアプリ本体へハードコードしない
- 外部商品DBで取得できた情報は必要時だけ利用
- メーカー判定用の小さなJANプレフィックス表だけをサーバー側に保持し、該当メーカーの公式サイトへ照会する
- 外部で見つからない商品はユーザーが一度登録し、端末内 `localStorage` にだけ保存
- 商品個別JAN辞書や全商品一覧はバンドルしない

## データ

- ログイン不要
- localStorage保存
- 店頭価格変更履歴を端末内に保存
- JSONバックアップ / 復元
- 端末データ初期化
- PWA manifest
- Service Workerでアプリ本体をオフラインキャッシュ

## 無料で使っている外部情報

- 西友ネットスーパーの公開見学ページ
- Open Food Facts

いずれも課金APIは使用していません。

## 起動

静的UIだけなら:

```bash
python3 -m http.server 8080
```

カメラは HTTPS または localhost が必要です。

西友検索・JAN商品詳細・Open Food Factsプロキシまで使う場合は Cloudflare Pages Functions 互換環境で起動します。

Functions:

```
functions/api/seiyu/search.js
functions/api/seiyu/product.js
functions/api/product/lookup.js
```

## ブラウザ対応

ネイティブの `BarcodeDetector` を利用し、端末が対応している EAN/UPC 形式だけを使います。対応ブラウザではライブカメラと画像ファイルの両方から読めます。未対応時はJAN手入力または商品名検索へフォールバックします。

## デモJAN

UI確認用の架空JANです。実商品ではありません。

- 4900000000016: クリームパン
- 4900000000105: カツ丼
- 4900000000201: コーラ 500ml

実商品を1つでも登録したカテゴリは、原則としてデモ商品より実商品を優先して提案します。

## 現在のデータの考え方

- `storePrice`: 実店舗で確認した価格
- `netPrice`: 西友ネットスーパー公開情報の参考価格
- `kcal`: 西友掲載値、Open Food Facts掲載値、またはユーザー登録値

栄養成分は「1個あたり」「1食あたり」「100gあたり」など掲載単位が商品ごとに異なるため、現段階では目安として扱います。

## テスト

外部テストサービスは必須にせず、Nodeだけで最低限の回帰確認ができます。

```bash
npm test
```

構文、JAN照合、無料商品DBフォールバック、西友代替検索、「もしあの時」記録、Service Worker、危険なイベント配線を確認します。

## 次に強くしたいところ

- 栄養成分の「1袋 / 1個 / 100g」単位をさらに正確に扱う
- 店頭レシートから価格更新を楽にする（有料OCRなしで検討）
- BarcodeDetector非対応ブラウザ向けの完全無料バーコード読取フォールバック
- 西友公開ページの構造変更に耐えるパーサ改善
- 朝セットの「満足優先 / 安さ優先 / 軽さ優先」切替
